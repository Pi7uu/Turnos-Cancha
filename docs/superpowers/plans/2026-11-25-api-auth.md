# API REST · autenticación Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Auth REST API (login/registro/logout/perfil with Django sessions) and the Flutter app logging in against it for real (replacing hardcoded credentials and in-memory users).

**Architecture:** Task 1 builds the Django side: DRF views + serializers + `/api/auth/` urls + `tests.py`. Task 2 adds the Flutter `ApiClient` (package `http`, manual cookie session) and wires the login screen (04) to `POST /api/auth/login/`. Task 3 wires the registro screen (05) to `POST /api/auth/registro/`, removes `credenciales.dart`/`usuarios_locales.dart` and their tests. Task 4: full verification + SDD spec + docs closure.

**Tech Stack:** Django 5 + DRF (`SessionAuthentication`, CSRF disabled via `auth.py`), `APITestCase`. Flutter: paquete `http` (primera dependencia nueva), `flutter_test` con cliente simulado. Flutter SDK en `C:\src\flutter` (invocar `C:\src\flutter\bin\flutter.bat`); backend se prueba con `python manage.py test` desde `src/BackEnd/`.

**Spec:** `docs/requerimientos/api-auth.md` (RD 2026-11-25). Endpoints de su §4; decisiones de su §8.

## Global Constraints

- **API** ( §4 del RD ): `POST /api/auth/registro/` `{email, password, nombre?}` → `201 {id, email, nombre}` + sesión; `POST /api/auth/login/` `{email, password}` → `200 {id, email, nombre}` | `401 {"error": "Email o contraseña incorrectos."}`; `POST /api/auth/logout/` → `204` | `401`; `GET /api/auth/perfil/` → `200` | `401`. Registro con email repetido → `400 {"error": "Ya existe una cuenta con ese email."}`. Sin contraseñas en respuestas. `nombre` default = parte local del email. Mensajes SIEMPRE en español.
- **Backend files**: `apps/turnos/api.py` ( vistas DRF: `registro`, `login`, `logout`, `perfil` — `SessionAuthentication` + `AllowAny` según endpoint ), `apps/turnos/serializers.py` ( `UsuarioSerializer` solo `id/email/nombre` ), `config/urls.py` agrega `path("api/auth/", include(...))` ( `apps/turnos/urls.py` nuevo ). `tests.py` con `APITestCase` ( BD en memoria ): los 4 endpoints en éxito y error ( 401/400 ), cookie de sesión seteada en login/registro, hash de contraseña en el registro.
- **Flutter client**: `lib/core/api/api_client.dart` — `ApiClient` con `http.Client` inyectable ( para tests `MockClient` ) + `baseUrl` ( default `http://10.0.2.2:8000` — documentar ); guarda `sessionid` de `set-cookie` y la manda en requests siguientes; métodos `login(email, password)`, `registro(email, password, nombre?)`, `logout()`, `perfil()` que devuelven el usuario o lanzan `ApiException(mensaje)` con el mensaje español del servidor ( o `No se pudo conectar. Intentá de nuevo.` ante errores de red ). `pubspec.yaml` + `http: ^1.2.0` ( única dependencia nueva ).
- **Pantalla 04** ( login ): el botón `Ingresar` llama a `ApiClient.login`; éxito → `onIngresar` ( entra al shell como hoy ); `ApiException` → error bajo el campo de contraseña; durante el request el botón muestra spinner y queda deshabilitado. **Pantalla 05** ( registro ): llama a `ApiClient.registro`; éxito → vuelve con el aviso `Cuenta creada`; email existente → error inline en el campo email; spinner igual. Los tests de widgets usan `ApiClient` con `MockClient`.
- **Eliminación**: `lib/features/auth/credenciales.dart`, `lib/features/auth/usuarios_locales.dart` y sus tests ( `credenciales_test.dart`, tests de usuarios locales ) — sus specs eran de etapas anteriores ( ruling documentado en el spec ). Los tests de widgets del login/registro se adaptan al cliente simulado.
- Idioma `es-AR` en todos los mensajes. Sin persistencia de sesión entre arranques ( la cookie vive en el `ApiClient` de la sesión ).

## Review Focus

1. **Contraseñas con hash y jamás en la respuesta** — el registro usa `create_user` y ningún endpoint devuelve `password`. Pinned: Task 1 tests de registro + perfil.
2. **Mensajes de error exactos en español** — `Email o contraseña incorrectos.` ( 401 ), `Ya existe una cuenta con ese email.` ( 400 ), `No se pudo conectar. Intentá de nuevo.` ( red ). Pinned: tests de API y de widgets.
3. **La cookie de sesión viaja** — login setea `sessionid` y `perfil()` la manda; `MockClient` en Flutter simula el flujo. Pinned: Task 2 test del cliente.
4. **Suite previa sin regresiones** — salvo los tests eliminados por ruling ( stores locales ) y los adaptados del login/registro, todo pasa ( 190 de frontend + tests de backend nuevos ). Pinned: suites completos.
