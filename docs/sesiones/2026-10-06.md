## 3. Debate de la base de datos (§1 de `requerimientos-backend.md`)

Decisiones tomadas:

| Decisión | Resultado |
|---|---|
| Motor | **SQLite local** por ahora; PostgreSQL cuando se escale (hosting / varios usuarios) |
| Login | `Usuario` **sin campo `username`** — `USERNAME_FIELD="email"` + manager propio `UsuarioManager` |
| Anti doble reserva | Tabla intermedia **`ReservaCancha`** con `fecha`/`hora_inicio` denormalizados + **índice único parcial** `(cancha, fecha, hora_inicio) WHERE ocupando` — la BD rechaza el conflicto aunque falle la app |
| Reserva con <24 h | **Nace `CONFIRMADA`** (si el plazo de vencimiento ya pasó, no tiene sentido crearla `PENDIENTE`) |
| Canchas | `F5-A`/`F5-B` hardcodeadas (no generalizar a varias sedes todavía) |
| Deja para después | Cierres excepcionales (feriados), precios/pagos |
